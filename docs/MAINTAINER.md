# 作者怎样维护这个公开项目

项目源码公开后，大家可以在GitHub查看、Fork、提Issue和Pull Request。采用非商业许可，因此不要把仓库标成MIT、Apache-2.0或“商业用途完全自由”的开源项目。

## 查看大家的反馈

进入仓库的Issues：普通使用问题、资料建议、商业授权咨询都有预设表格。看到涉及私人记录或密钥的内容时，不复制传播，提醒提交者删除并按需要处理泄露。Security中的私密漏洞报告与普通公开Issue分开。

## 接受改进

进入Pull requests，先看说明、修改内容和Source checks结果，再核对用户场景、资料出处和许可。通过测试不等于功能正确；涉及数据、AI或桌面行为时要按说明实际验证。确认后才合并，不需要给每个贡献者整个仓库的管理权限。

## 商业授权

收到咨询后先确认用途和涉及的组件，再约定私密联系方式与正式书面协议。申请、点赞、标注来源和普通讨论都不是授权。对外商业许可只能覆盖你有权许可的代码与素材；第三方依赖、外部贡献者的部分需要分别确认。存在金额、合同或权利争议时应让专业人员审阅，不根据一个GitHub标签就作法律保证。

## 发布新版

在独立分支改动，运行逻辑测试与相关桌面检查；版本号、README和变化说明对应真实功能。保留旧记录格式和知识卡ID。用Releases上传核对过的便携包，说明当前限制；不要把用户数据、私人邮箱或令牌混进源码、日志和安装包。

LICENSE是实际条款，README标签只是提示。许可证不能在技术上阻止他人复制，发现侵权仍需要证据与实际处置。项目目前仍是体验版；加密、跨机、专业审阅和长期效果尚未完成。
